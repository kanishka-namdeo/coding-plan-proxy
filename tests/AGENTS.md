# tests

## Purpose

Pytest test suite for the DashScope proxy. Three layers: unit tests (isolated classes/functions), integration tests (handler with mock upstream via aiohttp test server), and e2e tests (real API calls requiring an API key).

## Ownership

This directory owns all test code. Test fixtures and configuration live in `conftest.py`.

- **Fixture conventions**:
  - `dashscope_module` — returns the already-imported `dashscope_proxy` module (facade)
  - `rate_limiter` — creates a `RateLimiter` with tiny limits for fast tests
  - `mock_app` — mock aiohttp app with `rate_limiter` and `client_session`
  - `mock_request` — mock aiohttp request with default path `/v1/chat/completions`
  - `proxy_app` (integration) — creates proxy app with test rate limiter and mock client session
  - `_reset_provider_router` (integration, autouse) — resets the lazy provider router singleton before each test

- **Mock patterns**:
  - Integration tests use `aiohttp_client` fixture to create a test server with the proxy app
  - `aiohttp_client` is supplied by pytest-aiohttp, not by aiohttp — aiohttp registers no `pytest11` entry point, so its bundled plugin never loads and provides nothing; the suite is unrunnable from a runtime-only install and needs `pip install -r requirements-dev.txt`
  - Request doubles used for client-disconnect paths must stub `req.transport`, not `req.protocol.transport`: `_client_disconnected()` reads the public `Request.transport` first, and a bare `MagicMock()` auto-creates a truthy `transport` attribute, so a double stubbing only the protocol chain reads as permanently disconnected
  - Mock upstream servers are created inline in tests that need to simulate upstream responses
  - Mock-based files (`test_units.py`, `test_integration.py`, `test_audit_request_path.py`, `conftest.py`) intentionally keep the literal `qwen3-coder-plus` as an arbitrary model string — mock upstreams never validate the model ID and several routing assertions depend on that exact string. Do not "normalise" it to the catalog head
  - Tests patch `dashscope_proxy.TARGET_BASE` to point to the mock upstream
  - Use `_patch_target_base()` context manager (integration) to patch across all modules

- **Test configuration**:
  - `pyproject.toml` sets `asyncio_mode = "auto"`, `testpaths = ["tests"]`, and `asyncio_default_fixture_loop_scope = "function"`
  - `"function"` is mandatory: pytest-aiohttp's `aiohttp_client` is function-scoped, so a module-scoped loop scope breaks test-server teardown (103 teardown errors) — `"function"` also matches the pytest-asyncio default and silences the deprecation warning
  - Any module-scoped ASYNC fixture must therefore carry an explicit `loop_scope="module"` (e.g. `test_e2e_real.py::proxy_server`) or pytest-asyncio's scope-consistency assertion fails
  - Tests use `pytest.mark.asyncio` for async test functions
  - Rate limiter configs in tests use large limits (6000 RPM, 10M TPM) for fast execution
  - Backoff times are tiny (0.05s base) to keep tests fast

- **E2E requirements**:
  - `test_e2e_real.py` requires `DASHSCOPE_API_KEY` in `.env`
  - E2E tests make real API calls to DashScope and verify end-to-end behavior
  - Skip e2e tests if API key is not available
  - Set `DASHSCOPE_E2E_MODEL` in `.env` to probe a specific live model (this file reads `.env`; the root live scripts need the variable exported into the process environment); unset means the catalog head (`MOCK_MODELS["data"][0]["id"]`)

## Work Guidance

- Add unit tests for new pure functions and classes in `test_units.py`
- Add integration tests for new handler behavior in `test_integration.py`
- Use `aiohttp_client` fixture for integration tests that need a test server
- Mock upstream servers inline in tests; do not create shared mock server fixtures
- Patch constants via the facade (`dashscope_proxy.CONSTANT`), not direct imports
- Reset the provider router singleton before tests that exercise provider routing
- Keep test configs fast: large limits, tiny backoffs, small queue sizes
- Mark async tests with `@pytest.mark.asyncio` (or rely on `asyncio_mode = "auto"`)
- Headless Textual tests: cancel the app's workers first (`tui.workers.cancel_all()`) whenever the test drives a widget the poller also refreshes, reach `call_from_thread` only via `asyncio.to_thread`, and seed a table before asserting on a non-zero cursor — `move_cursor` clamps an out-of-range row to 0 rather than raising
- Never weaken an existing lock to make a change pass: re-pin it to the new contract (naming the contract in the docstring) or add a new lock alongside it
