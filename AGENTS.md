# DOX framework

- DOX is highly performant AGENTS.md hierarchy installed here
- Agent must follow DOX instructions across any edits

## Core Contract

- AGENTS.md files are binding work contracts for their subtrees
- Work products, source materials, instructions, records, assets, and durable docs must stay understandable from the nearest applicable AGENTS.md plus every parent AGENTS.md above it

## Read Before Editing

1. Read the root AGENTS.md
2. Identify every file or folder you expect to touch
3. Walk from the repository root to each target path
4. Read every AGENTS.md found along each route
5. If a parent AGENTS.md lists a child AGENTS.md whose scope contains the path, read that child and continue from there
6. Use the nearest AGENTS.md as the local contract and parent docs for repo-wide rules
7. If docs conflict, the closer doc controls local work details, but no child doc may weaken DOX

Do not rely on memory. Re-read the applicable DOX chain in the current session before editing.

## Update After Editing

Every meaningful change requires a DOX pass before the task is done.

Update the closest owning AGENTS.md when a change affects:

- purpose, scope, ownership, or responsibilities
- durable structure, contracts, workflows, or operating rules
- required inputs, outputs, permissions, constraints, side effects, or artifacts
- user preferences about behavior, communication, process, organization, or quality
- AGENTS.md creation, deletion, move, rename, or index contents

Update parent docs when parent-level structure, ownership, workflow, or child index changes. Update child docs when parent changes alter local rules. Remove stale or contradictory text immediately. Small edits that do not change behavior or contracts may leave docs unchanged, but the DOX pass still must happen.

## Hierarchy

- Root AGENTS.md is the DOX rail: project-wide instructions, global preferences, durable workflow rules, and the top-level Child DOX Index
- Child AGENTS.md files own domain-specific instructions and their own Child DOX Index
- Each parent explains what its direct children cover and what stays owned by the parent
- The closer a doc is to the work, the more specific and practical it must be

## Child Doc Shape

- Create a child AGENTS.md when a folder becomes a durable boundary with its own purpose, rules, responsibilities, workflow, materials, or quality standards
- Work Guidance must reflect the current standards of the project or user instructions; if there are no specific standards or instructions yet, leave it empty
- Verification must reflect an existing check; if no verification framework exists yet, leave it empty and update it when one exists

Default section order:
- Purpose
- Ownership
- Local Contracts
- Work Guidance
- Verification
- Child DOX Index

## Style

- Keep docs concise, current, and operational
- Document stable contracts, not diary entries
- Put broad rules in parent docs and concrete details in child docs
- Prefer direct bullets with explicit names
- Do not duplicate rules across many files unless each scope needs a local version
- Delete stale notes instead of explaining history
- Trim obvious statements, repeated rules, misplaced detail, and warnings for risks that no longer exist

## Closeout

1. Re-check changed paths against the DOX chain
2. Update nearest owning docs and any affected parents or children
3. Refresh every affected Child DOX Index
4. Remove stale or contradictory text
5. Run existing verification when relevant
6. Report any docs intentionally left unchanged and why

## User Preferences

When the user requests a durable behavior change, record it here or in the relevant child AGENTS.md

### Subagent Execution Model (durable instruction, 2026-09-12)

- Execute every user request via subagents: a single subagent for one coherent task, or multiple parallel subagents for independent work streams
- Dispatch parallel subagents only for truly independent tasks (disjoint files/concerns); run dependent work sequentially, never concurrently
- Never let parallel subagents edit the same files or shared state; parallelize read-only exploration freely, serialize mutations
- Give each subagent a self-contained prompt: full context, exact target paths, expected output, and a reminder to follow the applicable DOX chain
- Treat subagent output as unverified until integrated: review results, run the relevant verification, and complete the DOX pass before reporting back to the user

## Lessons

- Textual widgets default to `width: auto`. Any widget sharing a `1fr` row needs an explicit fractional width, or it grows to the whole row and starves its siblings to one blank cell. Never add a sibling to a row without adding its rule.
- A `DataTable` with `cell_padding = 0` has no implicit gap between columns: each column must be strictly wider than the longest string it can receive. A width that exactly fits its worst case makes neighbours read as one token.
- Measure TUI layout headlessly (`App.run_test(size=(w, h))` → `widget.size` / `virtual_size` / `content_size`) instead of eyeballing. Column widths plus padding, not the declared widths alone, decide whether a table scrolls.
- A percentage split imposes a hard cell budget on its children: the provider grid could not fit six columns below ~120 columns inside a 50%-wide panel. Give a data-dense table the whole width instead of squeezing its columns; the budget went away by removing the split, not by re-tuning widths.
- Textual's `:empty` pseudo-class means "has no child nodes", which is permanently TRUE for a `Static`. A `:empty { display: none }` rule on a Static hides it FOREVER, even while it holds text — drive visibility from content with a toggled class instead, and give the panel that class at compose time so it does not render as an empty box on the first frame.
- Textual gives every `dock: top` sibling the SAME row, so docked widgets paint over each other instead of stacking. Dock exactly one widget per region and let the rest flow.
- Textual CSS variables are resolved by overriding `get_css_variables` as an INSTANCE method and MERGING with `super()` — the override replaces the built-in set, and the mapping's keys carry no leading `$`. A variable's value may not itself be a `$reference`, so alias the already-resolved colours (`base["warning"]`) to stay theme-aware.
- A `DataTable` renders its own cells, so there is no element to hang a CSS class on. To style one cell, pass a `textual.content.Content` with `.stylize(style)` — not a class, and not `rich.text.Text` (which must never be imported directly).
- Derive one value from one function. The TUI re-branched on `circuit_open`/`circuit_failure_count` in three places and got three vocabularies; `circuit_glyph` now owns it.
- Never let one aggregate be formatted in two places. Two success-rate displays disagreed at idle because one used the raw float and one used the display guard.
- `DataTable.clear()` resets the cursor coordinate AND both scroll offsets, and the `cursor_coordinate` watcher schedules a DEFERRED `_scroll_cursor_into_view`. Restoring the scroll synchronously therefore loses — the deferred scroll lands afterwards and yanks the table back. Use `move_cursor(scroll=False)` plus `set_scroll`, and re-apply the offset from a `call_after_refresh` callback (FIFO, so it runs after every pending scroll-into-view). `set_scroll` also skips the validation a `scroll_to` does, which matters because `virtual_size` is still the pre-rebuild value until `on_idle`.
- Textual 8.2.8's `text-overflow: ellipsis` never reaches a Static's render path — verified: `height: 1` + `overflow: hidden` clips identically with and without it. An ellipsis that has to be VISIBLE must be produced in Python against the widget's real content width, and that width cannot come from the widget itself if the widget is `display: none` at the moment it is filled.
- `widget.styles.dock` returns the STRING `"none"` when unset, which is truthy — `if w.styles.dock` matches every widget in the tree. To find genuinely docked widgets use `w.styles.get_rule("dock") == "top"`.
- Never shadow a Textual hook with an attribute: `ProxyTUI._ready = True` broke `App._ready()`, an existing async method the startup path awaits (`TypeError: 'bool' object is not callable` at run time, not at import).
- The HTTP status envelope is one level DEEPER than the in-process status. `handlers.py` serves `/v1/proxy/status` as `{"rate_limits": rate_limiter.status(), "providers": …, "model_overlaps": …}`, while the TUI consumes the limiter status FLAT (`primary` / `secondary` / … at top level). Any consumer of the HTTP endpoint must unwrap `rate_limits` first, or `provider_grid_rows` finds nothing and `_validate_status` rejects the payload.
- A fail-loud guard must name the condition it OBSERVED, never a hypothesis about who owns the port. The screenshot harness refused to render `{"rate_limits", "providers", "model_overlaps"}` as "a foreign service squatting the port" — that is this proxy's OWN envelope, and the real fault was the missing unwrap. Recognizing your own payload by its keys is faster than inferring a stranger from them.
- When two consumers read the same logical payload at different nesting depths, pin BOTH shapes in a test: feed the HTTP wrapper shape and assert the derived view is non-empty, and assert the raw wrapper still yields nothing. Pinning only the happy path leaves the unwrap untested, because the unwrapped dict looks identical to a hand-built flat one.
- Coerce every number that crosses the provider boundary. Providers really do return `"total_tokens": "12345"` and `null`; left raw, the value reaches the handler's `total_tokens - estimated` subtraction and raises `TypeError`, which the upstream `except` clause does not catch — so the request 500s with its TPM reservation still held, and the quota leaks silently. Derive the coerced shape in ONE helper both extractors call, so a fix cannot land on one path and be forgotten on the other.
- A single poison entry can kill a background drain thread for the whole process lifetime. The session-log writer caught only `OSError` around `json.dumps`, so one non-serializable value raised `TypeError` out of the loop; nothing restarts it, and every later `log_async` becomes a silent queue-full drop. Serialize defensively (`default=str`), broaden the catch, AND put a broad `except` around the loop body — the thread must be immortal by construction, not by the callers' good behaviour.
- Never let a "fix" for an unreachable magnitude trade away a bounded-output invariant that the layout depends on. `_compact_number` divided past a saturated `"T"` suffix, losing 1000x of magnitude at 10**15 — but its 6-char ceiling is what sizes the Overview RPM/TPM columns, and `cell_padding = 0` means one oversized cell forces horizontal scroll. A local proxy cannot count 10**15 tokens, so keep the ceiling, document the tradeoff in the loop, and pin it.
- `now = now or time.monotonic()` silently discards a falsy-but-valid `now=0.0`. Use `time.monotonic() if now is None else now` on every injectable clock parameter; otherwise any deterministic fake-clock test that starts at zero silently reads wall time instead.
- An aliasing bug and a copy bug read the same at the call site. `entry["extra"] = record.extra_context` in a buffered log handler does not look wrong — it just means a buffered entry tracks the caller's dict and pins it alive. Snapshot anything you buffer.
- Swallowing `asyncio.CancelledError` is not "tolerating a disconnect". It means the task was cancelled, so the handler's own cancellation handlers never run and shutdown stalls. `_finalize_stream_response` tolerates the three connection errors only.
- Own the refund in ONE place, and clear the flag there. A boolean that tracks "do I still hold a reservation?" is only correct if the code that acts on it also updates it — 13 refund sites left the flag set, so any later cancellation path credited the bucket again. Note the refund direction is nastier than a leak: `refund` clamps at zero, so a double refund silently consumes OTHER in-flight reservations and inflates quota. Derive it from a single nested helper (`_refund_reserved()`) rather than patching call sites one at a time.
- A counter that is not windowed is lost forever if it is abandoned. `tpm_bucket.reserved` ages out only via recorded actuals, so a reservation dropped at any uncancellable-looking suspension point shrinks that provider's usable quota permanently — until restart. Audit the gap between "I took a resource" and "the caller learns the outcome" for ANY suspension point in between.
- Pre-bind a name that only one branch assigns. `upstream` was assigned solely inside the streaming branch, yet the shared `except` handlers dereferenced it — so a cancellation at that branch's `await` produced `UnboundLocalError` INSIDE the cancellation handler, masking the `CancelledError` it was written to propagate. An exception raised in a handler is not caught by sibling `except` clauses.
- A live check that can never pass is worse than no check: it reports red forever, so everyone learns to ignore it. A hardcoded model substring outlived the model it named. Derive the expectation from the same catalog constant the system uses, so it cannot rot again.
- Exiting 0 on failure makes a script useless to automation. Swallow-and-print plus a success exit code reports "fine" for a 401 from a missing key. Fail loudly and set the exit code.
